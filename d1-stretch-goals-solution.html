Reference answer

The agent lists first, then tries one delete command after another. These are the commands it asked for in the tests, in order.

Command the agent asked to runAnswerWhy
git status --short --ignoredYesIt only lists files. It changes nothing.
git clean -n -d -xYesThe -n flag makes it a dry run. It lists what it would delete and deletes nothing.
Remove-Item notes.txt or rm notes.txtNoIt deletes an untracked file. Git holds no copy, so the delete cannot be undone.
git clean -f -- notes.txt or git clean -f -xNoThe same delete through another command. The -f flag makes it real.

One request may join a list and a dry run, such as git status --short --ignored; git clean -n -d. Judge the part that does the most. Here both parts only list, so Yes is right.

Good enough means every delete has a No, and its reason says the delete cannot be undone. A No to a list command or a dry run is also fine when the reason is written down. It costs a slower answer and loses no work.

Why each layer is right or wrong:

Reference answer

This sheet gives no state for any issue. Your triage is your own. A good run has this shape:

  • The agent finds the issue by its title and reads that one file, or reads it with gh on routes A and B. It opens no code and no other issue.
  • It names the current state, then makes the case for one other state in a few points. Each point quotes the issue's own words, such as a guess in the report or a question the issue leaves open.
  • It says whether it would keep the current state, with reasons, and names the weak point the other case found.

Good enough means your decision answers the agent's strongest point. Keep your state if that point is already covered by your reason. Change it on paper if the point shows something your reason missed. Either way, write why.
