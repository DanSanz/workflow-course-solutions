Step 1. Set up your repo

Finished means a clone of your stack's repo with a remote named upstream. On route A or B it also has a remote named origin, your own private repo, and gh uses it.

git remote -v

Route C shows two lines for upstream only. Routes A and B also show two lines for origin, with your own GitHub name in the address. gh repo view then names your own repo.

PowerShell shows the progress that git and gh print in red. The command still worked if no line starts with fatal.

Step 2. Part 1, one question about the code

A good answer comes from the file CODEOWNERS at the repo root and names it.

Python
  • /pipeline/settings.py, the contributions technical leads.
  • /contracts/ and /src/generated/, the feed contract group.
  • /vendor/, the platform group.
.NET
  • /Directory.Build.props and /Directory.Packages.props, the member services technical leads.
  • /contracts/ and /src/MemberIngestion/Generated/, the feed contract group.
  • /vendor/, the platform group.

An answer that names other paths, or no file, goes on your paper as a mistake.

Step 3. Part 2, one Yes and one No

After the Yes, scratch.txt is in the repo root and holds hello. After the No, nothing is deleted.

git status --short

It shows only ?? scratch.txt.

The reason to refuse the delete. It changes far more than one file. It hits tracked files that the tests need. You can undo it only with git.

Python

It would delete 10 tracked files: requirements-dev.txt and nine fixtures in tests\fixtures.

.NET

It would delete six tracked fixtures in tests\fixtures.

Any reason that names what would change, whether it stays in the repo, or whether you can undo it, is good enough.

Step 4. Part 3, memory off

Claude Code

The file .claude\settings.json exists, and scratch.txt is gone.

Get-Content .claude\settings.json

It prints {"autoMemoryEnabled": false}.

git log --oneline -- .claude/settings.json

One line, Turn agent memory off.

GitHub Copilot

copilot config memory false prints Set memory to false in settings.json.

Get-Content "$env:USERPROFILE\.copilot\settings.json"

It holds "memory": false. Nothing changes in the repo.

The artefact you leave in the repo

  • Claude Code. .claude/settings.json holds "autoMemoryEnabled": false and is committed. No .claude/settings.local.json is committed.
  • GitHub Copilot. Your user settings hold "memory": false, or VS Code has "chat.copilot.memory.enabled": false. Neither is in the repo.

Done check

Claude Code 
claude -p "Reply with your auto memory directory, or NONE if it is off." --tools=

It prints NONE.

Why it passes. The project setting turns automatic memory off, so the agent has no memory folder for this repo. Without the file, the same command prints a folder under .claude\projects.

GitHub Copilot 
copilot config memory

It prints false.

Why it passes. The command reads the value that step 4 wrote to your user settings. Before step 4, on a new machine, it prints nothing.
