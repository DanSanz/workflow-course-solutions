Step 1. Part 1, the check command

Finished means scripts\check.ps1 runs the fast tests, stops at the first failure and exits with its code. It leaves the acceptance tests out. These are the lines that do the work in a finished script.

Python 
param([switch]$Spark)
$ErrorActionPreference = "Stop"
Set-Location (Split-Path -Parent $PSScriptRoot)
$env:PYTHONPATH = "src;vendor;."

function Step([string]$Name, [scriptblock]$Run) {
    Write-Host "== $Name"
    & $Run
    if ($LASTEXITCODE -ne 0) {
        Write-Host "check failed at: $Name"
        exit $LASTEXITCODE
    }
}

Step "unit and module tests" { python -m pytest tests/unit tests/modules -q }
if ($Spark) {
    $env:PYSPARK_PYTHON = "python"
    Step "spark tests" { python -m pytest tests/spark -q }
}
Write-Host "check passed"
exit 0
.NET 
$ErrorActionPreference = 'Stop'
Set-Location (Split-Path -Parent $PSScriptRoot)

$steps = @(
    @('build', 'src/MemberIngestion.Job'),
    @('test', 'tests/MemberIngestion.UnitTests'),
    @('test', 'tests/MemberIngestion.ModuleTests')
)

foreach ($step in $steps) {
    Write-Host "> dotnet $($step -join ' ')"
    & dotnet @step --nologo
    if ($LASTEXITCODE -ne 0) {
        Write-Host "Check failed at: dotnet $($step -join ' ')"
        exit $LASTEXITCODE
    }
}

Write-Host 'Check passed.'
exit 0

In Python, the -Spark switch adds the Spark tests. Your agent may add steps, such as a compile step. That is fine while the acceptance tests stay out and the exit code passes through.

Step 5. Part 4, the rule about feed dates

Python

Line 10 of docs/standards.md: feed dates are DD/MM/YYYY. Parse them with scheme_common.dates.parse_uk_date. Never parse a date by hand.

Step 8. Part 5, the glossary

Finished means GLOSSARY.md with 10 terms or more. Each term has a meaning and the names to avoid. One entry looks like this.

Python 
**Employer**:
An organisation that takes part in the scheme, reports its members
and pays contributions for them.
_Avoid_: Client, organisation, sender
.NET 
**Employer**:
An organisation whose staff are members of the scheme and which sends
the scheme a member file about them.
_Avoid_: Client, organisation, sender

The repo was built on these ten terms. Other terms are good enough if each has a meaning and the names to avoid.

Python

Employer, member reference, feed file, row, contribution period, due date, late contribution, unreadable row, rejected file, joiner.

The trap is to keep a rejected file and an unreadable row apart. A rejected file is refused whole. An unreadable row is reported and the run carries on. The runbook calls those rows rejected rows.

.NET

Employer, member reference, feed file, row, rejected file, joiner, date joined, service, load, file date.

The trap is the file date. It is the date the employer wrote in the header. The received date is the day the job loaded the file. Keep the two apart.

In after.txt the agent read GLOSSARY.md and used some of its terms. In test runs the answer was not shorter. If you see no change, that is a result too.
